二、哪些文件是真正源码
这不是只含压缩产物的发布包。dist/ 中的 JavaScript 是可直接编辑的 ES modules，CSS/HTML 和像素素材也全部包含。
入口：dist/index.html → dist/game.js。
状态与系统继承链（从底层到游戏实际入口）：
engine.js → expansion.js → frontier.js → rebuild.js → supply.js → echoes.js → districts.js → beyond.js → guidance-engine.js。
game.js 实际使用 guidance-engine.js 的 Engine、beyond-renderer.js 的 Renderer。
修改基础系统前检查各层覆盖的方法、freshState、migrateState、serialize / parse 的配合，避免绕开后续版本能力。
*-data.js：配方、地图、人物、事件、任务等配置。
*-ui.js：对应操作界面与动作路由；game.js 负责标题、设置、输入与总控制。
wayfinding.js：当前世界地图和本地地图。atlas.js 为已有地图能力的一部分，不要只改旧入口。
guidance-data.js / guidance-ui.js / guidance-engine.js：任务引导、目标定位、真实状态判定与保存。
player-session.js：正式存档、备份、偏好、导入恢复。
*-renderer.js、*-art.js、dist/assets/：Canvas 绘制、程序生成像素场景、全部五张 PNG 图集。
docs/：既有迭代记录、发布记录、设计与待验证事项。
tests/：自动化回归测试；scripts/：控制器检查、绘制检查和历史进度页生成。

三、运行与验证
无运行时后端，也不需要打包构建。请使用 HTTP 服务，不要双击 index.html 以 file:// 打开。
在解压后的项目根目录运行：
  python3 -m http.server 8000 --directory dist
Windows 若没有 python3 命令，可使用：
  python -m http.server 8000 --directory dist
然后打开：http://localhost:8000
仅试玩不需要安装 Node 依赖。

自动化测试需要支持 node:test 的 Node.js。本次使用 Node v24.19.0、Python 3.12.14。
  npm test
UI 控制器脚本另依赖 @napi-rs/canvas；原仓库 package.json 没有记录这项环境依赖，换电脑后先安装：
  npm install --no-save @napi-rs/canvas@0.1.100
  npm run test:ui
该 UI 脚本使用 DOM 替身与原生 Canvas，不等同真实浏览器界面验收。
本次导出重新执行结果：npm test 348 / 348 通过；npm run test:ui 通过。
